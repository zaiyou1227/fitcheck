# 大码尺码助手

> 不看 S/M/L，只看围度。一次录全身体数据，以后每家店都拿它去核对。

一个纯前端、离线可用的小工具：**把商品尺寸表解析成数字，和你的身体数据比对，直接告诉你哪个码能穿。**

名字里有"大码"，是因为它生于这个痛点；但引擎本身是通用的——
**高个子、宽肩、孕产、健身增肌、给家人买**，只要你有身体数据和商品尺寸表，它都能用。

同一件「5XL」，不同商家能差出 10cm。码数不是数据，围度才是。

---

## 它解决什么问题

| 痛点 | 这个工具怎么处理 |
| --- | --- |
| 尺码不统一，XL/5XL 没有客观含义 | 全部换算成 **腰围 / 臀围 / 大腿围 / 后裆长** 等实测数字 |
| 不知道自己的身体数据 | 21 项围度档案，厘米 / 英寸 / 市寸、公斤 / 斤实时互转 |
| 买裤子总勒裆、往下坠 | 单独算**后裆长**（大体重最关键、商家最常不写的一项） |
| 商品太多，一个个比太慢 | **批量比对**：粘多个尺寸表，自动解析 + 排序，直接告诉你能不能穿 |
| 不知道店靠不靠谱 | 9 条筛店标准打分，三条关键项缺一条就不建议长期买 |
| 海淘算不清划不划算 | 把退货概率折进「单件真实成本」 |
| 数据怕丢 | 导出文件 + 分享链接，换设备、清缓存都能恢复 |

## 四个页面

- **尺码档案** `profile.html` — 录 21 项身体围度，自动推算裤子和上衣该找的成衣尺寸
- **裤子换算** `pants.html` — 只算裤子；支持「从身体档案读」和「量一条旧裤子」两种来源
- **批量比对** `compare.html` — 粘多个商品尺寸表，自动解析 + 匹配 + 排序；带书签一键采集
- **筛店清单** `guide.html` — 9 条标准打分 + 海淘真实成本计算器 + 男女装搜索词

## 批量比对怎么用

三种输入方式：

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| **粘贴尺寸表** | 所有平台 | 最稳。把详情页的尺寸表整段复制粘进来，多个商品用 `---` 分隔 |
| **粘贴链接** | 品牌官网 | 无登录墙、带 CORS 头的站点可以自动抓 |
| **书签一键采集** | 任意商品页 | 用你自己已登录的浏览器，绕过登录墙 |

### 为什么不能直接抓淘宝/京东

实测确认：这两个平台对非登录访问返回**登录页**，页面内容由 JS 动态渲染。
连真实浏览器（带正常 UA）都会跳登录。这不是工具的问题，是平台限制。

所以设计成「能自动的自动，抓不到的用粘贴兜底」——
**粘贴尺寸表反而比抓取更通用**，因为它不依赖页面结构，也不受反爬影响。

### 判定逻辑

成衣实测值 − 身体净围 = **松量**。每个部位按品类有不同的合理区间：

- **只能偏大**（后裆、袖长、衣长）：偏长只是裤腰高/袖口长，不算穿不下
- **只能偏小或刚好**（胸围、臀围、大腿围）：小了就是真穿不下
- **软性指标**（腰围、肩宽）：偏小可以当低腰/落肩穿，扣分但不判死刑

结果分五档：**很合适 / 可以穿 / 偏大 / 偏紧 / 穿不下**，
「穿不下」会直接告诉你差几厘米。

**这套规则对所有体型都成立**，大码只是最容易触发"穿不下"的场景。

## 使用

直接打开 `index.html` 即可，无需安装、无需联网。手机浏览器打开后可以「添加到主屏幕」，
像 App 一样用，断网也能打开。

**最快的上手路径：**

1. 量 5 项就能开始：腹围、臀围、大腿围、立裆深、胸围
2. 去「裤子换算」，看「该找什么数」
3. 把生成的话复制给客服。对方报不出后裆长和大腿围，就换一家
4. 录完记得去「尺码档案 → 数据备份」导出一次

## 数据与隐私

- **所有数据只存在你自己的浏览器里**（`localStorage`），不经过任何服务器，没有埋点，没有账号
- 分享链接把你的数据压缩后放在 URL 的 `#` 后面——**这条链接等同于你的身体数据，别公开发布**
- 清缓存 / 换设备会丢数据，所以提供了导出文件和分享链接两种备份

## 一些实现上的取舍

**为什么不按码数对表。** 码数是营销单位，不同厂家自定义。所以整个工具只做一件事：
把身体数据换算成**成衣尺寸区间**，让商家用数字回答。

**为什么单位跟着数值走。** 存储结构是 `{ v: 130, u: "cm" }`，
所以切换显示单位不会改变真值，换设备、换单位都不丢精度。

**为什么小腿围、脚踝围不参与推算。** 商家几乎不标这两项，硬推一个区间只会误导。
它们只进档案，不生成目标值——但填了小腿围，膝围会自动改按它推算，并明确标注这是推算值。

**为什么区分「臂长」和「袖长」。** 袖长有两种量法（肩点到腕 / 后颈经肩点到腕），
差 9–12cm。填了两个袖长时，工具会检测差值是否合理，不合理就警告。

## 本地开发

```bash
# 需要 Node.js 18+
npm install

# 跑测试（107 项，含真实页面加载与交互）
npm test

# 起本地服务预览（用 file:// 打开也可以，但 Service Worker 需要 http）
npx serve public -l 4173
```

## 部署

### GitHub Pages（推荐）

见 [docs/deploy.md](docs/deploy.md)。仓库根目录的 `public/` 就是要发布的站点，
不需要构建步骤。

### 其他静态托管

`public/` 目录可以直接丢到任何静态托管：Cloudflare Pages、Netlify、Vercel、
对象存储、甚至自己的 NAS。**没有构建、没有依赖、没有后端。**

> 注意：Service Worker 和「添加到主屏幕」需要 **HTTPS**（`localhost` 例外）。

## 目录结构

```
public/

  js/data.js          数据层：单位、档案、导出导入、链接编码
  js/app.js           共享 UI：导航、toast、备份面板
  js/vendor-lz-string.min.js   zlib 压缩，用于把数据塞进链接
  sw.js               Service Worker，离线缓存
  manifest.webmanifest
  icons/
tests/
  run-tests.cjs       集成测试（起本地 HTTP 服务 + jsdom）

scripts/
  make_icons.py       从 SVG 生成各尺寸 PNG 图标
docs/
  deploy.md           部署与一键上传说明
```
